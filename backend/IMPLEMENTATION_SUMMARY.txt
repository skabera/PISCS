✅ BACKEND IMPLEMENTATION COMPLETED:

1. DATABASE TABLE: insurance_documents
   Location: PISCS SQLite database
   Columns: id, invitation_id, preacher_id, uploaded_by_pastor_id, 
            document_url, document_type, file_name, uploaded_at

2. API ENDPOINTS ADDED: (4 new routes in server.js, lines 1551-1707)
   
   a) POST /api/insurance/upload
      • Upload insurance document after approval
      • Only pastors can upload
      • Requires: multipart form with file + invitation_id
      • Response: Document ID and URL
   
   b) GET /api/insurance/invitation/:id
      • Retrieve all insurance documents for an invitation
      • Access: Pastor, preacher, secretaries, admins
      • Returns: Array of documents with metadata
   
   c) GET /api/insurance/preacher/:id
      • Get all insurance documents for a preacher
      • Access: Preacher, relevant secretaries, admins
      • Returns: All documents across all invitations
   
   d) DELETE /api/insurance/:id
      • Delete insurance document
      • Access: Uploader or admin only
      • Audit logged

   ✓ Audit logging for all actions (CREATE, DELETE)
   ✓ Push notifications to preacher when uploaded
